**Задача**  
Создать сервис для отправки уведомлений пользователям.
**Требования**  
Пользователь может получать уведомления через:
- Email
- SMS
- Telegram

Нужно обеспечить надежную доставку - если один способ не сработал, попробовать другой.  

**Реализация**  
1. Django Framework. Есть одна модель и одна, соответствующая ей миграция.
2. Реализован один REST API (с помощью DRF) эндпоинт api/send для отправки задачи с полезной нагрузкой в виде user_id, заголовка, тела сообщения/уведомления. Формат успешного ответа api/send предполагает id уведомления и статус "взято в работу" (queued).  
3. Обработка сообщений через Celery. В текущей конфигурации (базовой/простой/без дополнительной конфигурации) последовательность обработки задач не гарантирована.  
4. Мониторинг работы Celery ручной через Flower.  
5. Решение упаковано в Docker.  

**Предупреждения**  
(!) nginx здесь - это не подготовка к развертыванию на прод, а решение проблем с запуском.  
(!) Конфигурация sms, email, telegram только для примера и не является рабочей, поэтому результатом работы без подключения рабочих сервисов будет попытка отправить сообщение по каждому каналу, неудача и повторы попыток.  
(!) Конфигурация (.env) присутствует для примера. В реальном проекте используется env.example  

**Запуск**  
docker-compose up --build

**Проверить можно через:**  
- браузер: 127.0.0.1:8080/api/send/
- curl: curl -X POST http://localhost:8000/api/send/ -H "Content-Type: application/json" -d '{"user_id":"you@mail.com","title":"Тест","message":"Работает!"}'

Проверить/пронаблюдать работу очереди можно через Flower:
- браузер: 127.0.0.1:5555
